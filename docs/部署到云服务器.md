# 把本地新版本部署到云服务器（阿里云 ECS + Docker）

> 适用场景：本地已经能正常跑；服务器上已经有一个能访问的旧版本，现在要把新版本（主动推送 + RAG 混合检索）覆盖上去。
> 环境假设：CentOS + Docker，项目放在 `/project`，容器名 `campus`，镜像名 `campus-agent`，端口 `8000`。

---

## 0. 先理解三件事（30 秒看懂为什么要这么做）

1. **服务器上跑的不是你的源码目录，而是用源码“烤”出来的镜像。**
   Docker 镜像是构建那一刻的快照。你改了本地代码，服务器上的镜像里还是旧代码，所以每次改完都要 `docker build` 重新烤一遍。
2. **容器一删，容器里的数据库就没了。**
   所以要把 `data` 目录挂到宿主机（`-v` 参数）。挂上之后，重建容器不会丢审批记录、通知和上传的文档。
3. **密钥不进镜像。**
   DeepSeek / 高德 的 Key 通过启动时的 `-e` 注入（项目里的 `.dockerignore` 把 `.env` 排除在镜像之外了）。
   镜像里没有 Key，把镜像传给别人也不会泄露。

## 1. 本地：准备要上传的东西

**推荐做法**：本地跑一次打包脚本，只上传一个 zip（约 0.5 MB），云服务器上解压即可——见第 4.0 节。

```powershell
cd E:\pythonProject1\bhu_campus_agent
.venv\Scripts\python scripts\pack_for_upload.py
```

它会自动排除 `.venv`、`data`、`logs`、`__pycache__`、`.env`，产出 `E:\pythonProject1\bhu_campus_agent_upload.zip`。压缩包里已经带了项目自用的 `dockerfile` 和 `.dockerignore`，所以一个包就够了。

如果偏好手动一个个传，对应关系是这三样：

| 本地路径 | 传到服务器 | 说明 |
|---|---|---|
| `E:\pythonProject1\dockerfile` | `/project/dockerfile` | 构建说明（这次必须重传，见下面的注意点） |
| `E:\pythonProject1\.dockerignore` | `/project/.dockerignore` | 告诉 Docker 哪些目录不用打进镜像，能大幅加快构建 |
| `E:\pythonProject1\bhu_campus_agent\`（整个目录） | `/project/bhu_campus_agent/` | 源码 + 知识库文件 |

**不要传**的东西及原因：

| 不上传 | 原因 |
|---|---|
| `bhu_campus_agent\.venv\` | Windows 的虚拟环境在 Linux 上用不了，而且有几百 MB，传上去纯浪费 |
| `bhu_campus_agent\data\` | 里面是你本地的测试数据库（请假单、工单、通知记录），传上去会把线上数据覆盖成本地测试数据 |
| `bhu_campus_agent\logs\` | 本地日志，没有上传价值 |
| `bhu_campus_agent\.env` | 里面有你的真实 Key，服务器上单独配置即可 |
| 各种 `__pycache__\` | Python 缓存，服务器会重新生成 |

> 注意：`.gitignore` / `.dockerignore` 只对 git 和 docker 构建生效，**文件上传（SFTP 拖拽）不看这些规则**，所以“不要传什么”需要你自己在拖拽时避开。

### 这次必须重传 `dockerfile` 的原因

新版把依赖清单统一成一份：Dockerfile 从 `bhu_campus_agent/requirements.txt` 读取，而这份清单新增了 `numpy`、`pypdf`、`openpyxl`、`python-docx`、`python-multipart`（RAG 知识库和文件上传接口需要）。

如果服务器上还是旧 Dockerfile，构建出来的镜像里没有这些包，一启动就会出现 `ImportError` 或者后台知识库直接报错。传完可以用第 5 步的命令确认。

## 2. 连上服务器（XTerminal）

1. 打开 XTerminal，进入你之前保存的那个 SSH 会话（`root@你的公网IP`）。
2. 切到文件面板：XTerminal 上方一般有「终端 / 文件（SFTP）」的切换标签，点「文件」。
3. 在文件面板的地址栏输入 `/project` 回车，确认能看到 `bhu_campus_agent` 目录。

如果你习惯命令行，也可以用 `sftp` 连接，效果一样；下面第 4 步末尾给了纯命令行的替代方案。

## 3. 服务器：先备份，再动手（1 分钟，强烈建议）

```bash
cd /project
cp -r bhu_campus_agent bhu_campus_agent.bak.$(date +%Y%m%d)
docker images | grep campus-agent
```

每一条在做什么：

- `cd /project`：进入项目上级目录。
- `cp -r ...`：把整个项目目录复制一份，名字带上今天的日期（例如 `bhu_campus_agent.bak.20260928`）。万一新版本有问题，`mv` 回来就能恢复。
- `docker images | grep campus-agent`：看一眼当前镜像，**记下那个 IMAGE ID**（一串 12 位字符）。回滚时可以拿旧镜像直接启动，比重新构建快得多。

## 4. 上传文件

### 4.0 推荐：先压成一个 zip 再传（一条命令，几乎不会卡）

**为什么不要直接拖整个文件夹**：本地 `.venv` 有近万个文件、四百多 MB，但它们只对 Windows 有效，传上去也用不了。SFTP 是一个文件一个文件地传，近万个小文件会让面板长时间没有反应，看起来就像卡死了，还常常中途断线。

项目里已经带了打包脚本，在本地项目目录执行：

```powershell
cd E:\pythonProject1\bhu_campus_agent
.venv\Scripts\python scripts\pack_for_upload.py
```

它会自动排除 `.venv`、`data`、`logs`、`__pycache__`、`.env`，在 `E:\pythonProject1\` 下生成 `bhu_campus_agent_upload.zip`（实测 52 个文件、约 0.5 MB）。

然后在 XTerminal 里：

1. 把 `bhu_campus_agent_upload.zip` 上传到 `/project`（一个文件，几秒钟）。
2. 在服务器上解压覆盖：

```bash
cd /project
cp -r bhu_campus_agent bhu_campus_agent.bak.$(date +%Y%m%d)     # 先备份，出问题能回滚
python3 -m zipfile -e /project/bhu_campus_agent_upload.zip /project/bhu_campus_agent/
ls bhu_campus_agent                                             # 应看到 app/ seed/ docs/ requirements.txt
```

`python3 -m zipfile -e 压缩包 目标目录` 就是"解压到指定目录"，同名文件会被覆盖，多余文件不受影响（所以不会误删服务器上的东西）。如果服务器装了 `unzip`，`unzip -o bhu_campus_agent_upload.zip -d bhu_campus_agent/` 效果一样。

3. 顺手清掉服务器上那个用不了的 Windows 虚拟环境（可选，能省四百多 MB 磁盘）：

```bash
ls /project/bhu_campus_agent/.venv          # 看到 Scripts/ 就说明是 Windows 的，Linux 用不了
rm -rf /project/bhu_campus_agent/.venv
```

> 命令前先 `ls` 确认一下再删，养成习惯。

### 4.1 逐个拖拽（文件少的时候可以用）

先传两个构建文件：

把本地的 `dockerfile` 和 `.dockerignore` 拖进文件面板的 `/project` 目录，弹出覆盖提示时选“覆盖/全部覆盖”。

### 4.2 传项目目录（接 4.1）

**先进到 `/project/bhu_campus_agent`**，再把本地 `bhu_campus_agent` 目录**里面的内容**（`app`、`seed`、`scripts`、`tests`、`docs`、`requirements.txt`、`run.py`、`.env.example` 等）拖进去覆盖。

> 容易踩的坑：如果直接在 `/project` 里拖整个 `bhu_campus_agent` 文件夹，可能变成 `/project/bhu_campus_agent/bhu_campus_agent/...` 这种双层目录，代码其实没更新。传完用第 5 步的命令确认一下。

> 隐藏文件注意：`.dockerignore` 以点开头，有些 SFTP 面板默认不显示隐藏文件。传完后在终端里 `ls -a /project` 确认它真的在。

### 4.3 命令行替代方案

如果拖拽太慢或者文件太多，可以在本地 Windows 的 PowerShell 里用 `scp`：

```powershell
# 传项目内容（覆盖同名文件，不会删除服务器上的多余文件）
scp -r E:\pythonProject1\bhu_campus_agent\* root@你的公网IP:/project/bhu_campus_agent/

# 传两个构建文件
scp E:\pythonProject1\dockerfile E:\pythonProject1\.dockerignore root@你的公网IP:/project/
```

（`scp` 会提示输入服务器密码，输你阿里云实例的 root 密码就行。）

## 6. 服务器：配置密钥（`.env`）

```bash
cd /project/bhu_campus_agent
mkdir -p data
vi .env
```

`vi` 的操作：按 `i` 进入编辑模式 → 输入/修改内容 → 按 `Esc` → 输入 `:wq` → 回车保存退出。

文件内容（Key 换成你自己的）：

```ini
DEEPSEEK_API_KEY=sk-你的Key
AMAP_API_KEY=你的高德Web服务Key
```

说明：

- `mkdir -p data`：确保数据目录存在（`-v` 挂载需要它）。已经有的话不会报错。
- **注意**：这个 `.env` 只在「不进 Docker、直接用 Python 跑」时生效。项目的 `.dockerignore` 把 `.env` 排除在镜像之外（避免密钥被烤进镜像），所以跑容器时 Key 必须在 `docker run` 里用 `-e` 传，第 8 步的命令里有。
- 检查是否写对：`cat .env`。

## 7. 服务器：构建镜像

```bash
cd /project/bhu_campus_agent
docker build -t campus-agent .
```

> 用哪种上传方式，决定了构建目录在哪：
> **压缩包方式（4.0）**：项目里自带 `dockerfile`，所以直接进 `/project/bhu_campus_agent` 构建（就是上面这条）；
> **分别拖拽方式（4.1）**：`dockerfile` 在 `/project`，就改成 `cd /project && docker build -t campus-agent .`。
> 两条命令建构出来的镜像名字一样，后面 `docker run` 完全一致，用哪种都行。

在做什么：Docker 按 `dockerfile` 的步骤执行——装 Python 依赖（走阿里云 pip 源）、换 Debian 阿里云源、装 Playwright 的 Chromium（浏览器 MCP 用）、把项目拷进镜像。

- 第一次构建比较慢（要下 Chromium，**10 分钟左右**），可以先去干别的；重复构建因为有缓存会快很多。
- 看到最后一行 `naming to docker.io/library/campus-agent` 就是成功了。
- 想看进度细节：`docker build -t campus-agent . --progress=plain | tail -20`。

## 8. 服务器：重建容器

```bash
docker rm -f campus

docker run -d --name campus --restart=always -p 8000:8000 \
  -v /project/bhu_campus_agent/data:/app/data \
  -e PYTHONUNBUFFERED=1 \
  -e DEEPSEEK_API_KEY=sk-你的Key \
  -e AMAP_API_KEY=你的高德Key \
  campus-agent
```

> **两个 Key 都要用 `-e` 传，别只传 DeepSeek。**
> 项目里的 `.dockerignore` 把 `.env` 排除在镜像之外了（密钥不该烤进镜像，镜像万一发给别人就泄露了），
> 所以容器里读不到服务器上那个 `.env`。只传 DeepSeek 的话，高德地图 MCP 会是 offline，
> 路线规划、天气、周边搜索这些功能都不能用。

每个参数的含义：

| 参数 | 含义 |
|---|---|
| `docker rm -f campus` | 删掉旧容器（先删才能用同名新建）。因为数据在宿主机的 `-v` 目录里，删容器不影响数据 |
| `-d` | 后台运行，不占着终端 |
| `--name campus` | 容器叫 campus，后面 `docker logs campus` 就是看它 |
| `--restart=always` | 容器崩溃或**服务器重启后自动拉起**，这是“重启电脑后别人还能访问”的关键 |
| `-p 8000:8000` | 把服务器的 8000 端口映射到容器的 8000，外网访问入口 |
| `-v /project/bhu_campus_agent/data:/app/data` | 把宿主机 data 目录挂进容器，数据库/上传文件留在宿主机，重建容器不丢 |
| `-e DEEPSEEK_API_KEY=...` | 注入 DeepSeek Key。容器里读不到宿主机上的 `.env`（被 .dockerignore 排除了），所以必须在这里传 |
| `-e AMAP_API_KEY=...` | 注入高德 Key。少这个的话高德 MCP 会 offline，路线/天气/周边搜索都用不了 |
| `-e PYTHONUNBUFFERED=1` | 让 Python 的 `print()` 立刻写日志。不加的话 `docker logs` 里看不到 `[init]` 那几行（被缓冲区扣住了），会误以为知识库没加载 |
| `campus-agent` | 用哪个镜像启动（放在最后） |

## 9. 服务器：验证部署成功

### 9.1 服务是否起来

```bash
docker ps
docker logs campus --tail 30
curl -s http://127.0.0.1:8000 | head -5
```

日志里应该出现这几行（内容对得上就说明新版本生效了）：

```
[init] 知识库索引分块数：78
[init] 检索索引：BM25 + 向量（后端 lsa，维度 128，向量数 78，文档 73 篇）
[init] 外部MCP [amap] -> online
```

> 新版把外部 MCP 的启动放到了后台：网页**秒开**，浏览器 MCP 和高德 MCP 会在几秒后
> 自动变成 online（日志里后出现那两行是正常的）。这样就不会出现"服务起来了但网站
> 十几秒打不开"的情况。

`curl` 能打印出 HTML（`<!DOCTYPE html>`）说明容器内服务正常。

### 9.2 外网能否访问

浏览器（或手机）打开 `http://你的公网IP:8000`。

打不开时依次查：`docker ps` 里 campus 是否 Up → 阿里云安全组是否有 TCP 8000 入方向规则（授权对象 `0.0.0.0/0`）→ 服务器防火墙是否放行（`systemctl status firewalld`，inactive 就是不拦）。

### 9.3 功能抽查（4 项，2 分钟）

1. 用 `student / student123` 登录，问「北校区水暖班维修电话是多少」→ 应该答出 `63041132`。
2. 管理后台 `/admin` → 知识库 → 拉到底部「检索测试」→ 输入「怎么去东校区」→ 能看到 BM25 / 向量 / 融合三路结果。
3. 主动推送：教师端批一条请假 → 切回学生端，**5 秒内**出现右上角气泡 + 铃铛红点。
4. 上传功能：后台知识库「⬆ 上传文件入库」传一个 md/txt 文件 → 列表里能看到它。

## 10. 常见问题

| 现象 | 原因 / 解决 |
|---|---|
| **上传时面板卡住不动** | 十有八九是在传 `.venv`（近万个小文件、四百多 MB），SFTP 一个个传会长时间没反应。取消传输，改用第 4.0 节的压缩包方式。已在服务器上的 `.venv` 确认后删掉：`ls /project/bhu_campus_agent/.venv` 看到 `Scripts/` 就是 Windows 的，`rm -rf /project/bhu_campus_agent/.venv` |
| 传完发现多了一层目录 | 在 `/project` 里拖了整个文件夹，变成 `/project/bhu_campus_agent/bhu_campus_agent/...`。把内层内容挪上来：`mv /project/bhu_campus_agent/bhu_campus_agent/* /project/bhu_campus_agent/`，再删掉空的内层目录 |
| `docker build` 报 `failed to read dockerfile: no such file or directory` | 你不在 `/project` 目录，或者 `dockerfile` 没传上去。先 `cd /project && ls -la` |
| 构建成功但启动就退出（`docker ps -a` 显示 Exited） | `docker logs campus` 看报错。常见是缺依赖（Dockerfile 是旧的）或 `.env` 里 Key 写错 |
| 页面能打开但问答报 500 | `docker exec campus printenv DEEPSEEK_API_KEY` 看 Key 在不在 |
| 路线/天气/周边搜索用不了，日志里 `[amap] -> offline` | `docker exec campus printenv AMAP_API_KEY`。新版 `.dockerignore` 排除了 `.env`，容器读不到服务器的 `.env`，必须在 `docker run` 里加 `-e AMAP_API_KEY=你的Key` 重建容器 |
| 知识库检索没结果、日志显示 0 块 | `docker exec campus ls /app/seed/kb_files`：文件不在就是没进镜像，重新 build；文件在就进后台点「重新扫描知识文件」 |
| `docker logs` 里看不到 `[init]` 开头的行 | 不是没启动，是 stdout 被缓冲了。加 `-e PYTHONUNBUFFERED=1` 重建容器即可（新版 Dockerfile 已经默认打开）。想立刻确认新版本是否在跑，用 `curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8000/api/notifications`：**401 = 新版本**（接口在，只是没登录），404 = 旧版本 |
| 日志停在 `Waiting for application startup` 不动 | 旧代码是在启动阶段同步拉起外部 MCP（要下载/启动 Chromium、还要连高德远程服务），这期间 uvicorn 不接收请求。**新版已改成后台启动**，重启后网页秒开；如果你看到的还是旧行为，说明镜像没更新，重新 build 一次。临时判断：等 40~60 秒再看日志，或 `docker stats --no-stream campus` 看 CPU 是否在动 |
| 后台页面还是旧样式 | 浏览器缓存，按 **Ctrl+F5** 强刷 |
| 推送不弹 | 前端 5 秒轮询一次，稍等一下；还是没反应就强刷页面。DB 里有没有记录：`docker exec -i campus python -c "import sqlite3;c=sqlite3.connect('/app/data/campus.db');print(c.execute('select count(*) from notifications').fetchone())"` |
| 重启服务器后别人访问不了 | 检查两处：`docker inspect -f '{{.HostConfig.RestartPolicy.Name}}' campus` 是否输出 `always`；`systemctl is-enabled docker` 是否输出 `enabled`（没有就执行 `systemctl enable docker`） |

## 12. 出问题怎么回滚

方式一：用备份目录重新构建

```bash
cd /project
mv bhu_campus_agent bhu_campus_agent.new
mv bhu_campus_agent.bak.20260928 bhu_campus_agent
```

方式二：直接用第 3 步记下的旧镜像 ID 启动（最快）

```bash
docker rm -f campus
docker run -d --name campus --restart=always -p 8000:8000 \
  -e DEEPSEEK_API_KEY=sk-你的Key \
  -e AMAP_API_KEY=你的高德Key <旧的IMAGE_ID>
```

两种方式都不会动宿主机 `data` 目录里的数据。
